# Lint

Every style rule is enforced by a tool, not by a review. A rule is switched on only after a count shows which files it would refuse. Three enforcers:

- **`@widgetarium/eslint-plugin`**: the framework's style rules, the ones every project built on Widgetarium follows. `npm run lint:style` runs it on this repository; `create` lays it into every project.
- **`node tools/lint-code.mts <roots>`**: this repository's own rules (comments, sizes, typing, casts, the `server` condition).
- **Types and starters**: `npm run test:types`, and the refusals `app()` and `server()` throw at start.

## A project's config

```js
import widgetarium from "@widgetarium/eslint-plugin";

export default [...widgetarium.configs.recommended, { rules: { "@widgetarium/no-choice-strings": "off" } }];
```

`configs.recommended` switches every rule on, as an error except `handler-ownership`, a warning. Its parser is Babel's, so the rules read TypeScript with no `typescript` JS API.

## Every style rule and what enforces it

| Rule                                                                                                                                                                                                                                                                                                                                    | Enforced by                                                                                 |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| a building block is a named exported const, PascalCase, ending with its kind; a handler is `<Request>Handler`                                                                                                                                                                                                                           | `building-block-names`                                                                      |
| a module is `<Domain><Side>Module`, so a handler file shows its side                                                                                                                                                                                                                                                                    | `building-block-names` (`serverModule(` → `ServerModule`, `clientModule(` → `ClientModule`) |
| fluent chains, never an options object                                                                                                                                                                                                                                                                                                  | types: `guard()`, `middleware()` take no argument, `handler(X, Module)` takes two           |
| `.handle` ends a behaviour; a server handler's `.handle` exists only once a guard covers it                                                                                                                                                                                                                                             | types; `server()` refuses an uncovered handler                                              |
| guard coverage: `PublicGuard` or a guard needing a user, on the module or the handler                                                                                                                                                                                                                                                   | types; `server()`                                                                           |
| strings only as free-form data (request and module names)                                                                                                                                                                                                                                                                               | `no-choice-strings`                                                                         |
| a contract imports only `shared/schema`, `@widgetarium/core/requests` and shared packages                                                                                                                                                                                                                                               | `contract-imports`                                                                          |
| `<pkg>/module` of a server module only in a server app; of a client module only in a client app or host; only the three entries                                                                                                                                                                                                         | `module-imports`; the `server` export condition as the second line                          |
| module.ts holds only the module definition                                                                                                                                                                                                                                                                                              | `module-definition`                                                                         |
| a server module gates `./module` and `./adapters` behind `server` and has no `ui/`                                                                                                                                                                                                                                                      | `server-module`                                                                             |
| only `apps/server` resolves the `server` condition                                                                                                                                                                                                                                                                                      | `server-condition` (tools/lint)                                                             |
| feature layout: leaf or group, two levels, a feature holds contract.ts, handlers.ts, ui/, lib/; the top holds module.ts, features/, shared/, adapters/, generated/; ui only `.tsx`; no top-level `let`; request names `<module>/<kebab>`; no import of another feature's ui/ or lib/; an adapter's parts reached only through its entry | `feature-layout`                                                                            |
| ownership: an id from the input reaching a port with no resolving guard; a server handler calling another `*Handler.handle(`                                                                                                                                                                                                            | `handler-ownership` (warning)                                                               |
| the generated entries are fresh and open with the generated header                                                                                                                                                                                                                                                                      | `widgetarium generate --check` in `test:generated`                                          |
| comments: only `TODO:` and `TRADE-OFF:`                                                                                                                                                                                                                                                                                                 | `comments` (tools/lint), the edit hook                                                      |
| early returns                                                                                                                                                                                                                                                                                                                           | `early-return` (tools/lint)                                                                 |
| sizes: a file over 400 lines, a function over 80                                                                                                                                                                                                                                                                                        | `file-size`, `function-size` (tools/lint)                                                   |
| type budget: 200 handlers over 1.2x the recorded instantiations                                                                                                                                                                                                                                                                         | `test:type-budget`                                                                          |
| no foreign code in the browser bundle                                                                                                                                                                                                                                                                                                   | `test:web-canvas-bundle`                                                                    |
| split by area, not by line count                                                                                                                                                                                                                                                                                                        | no tool: the `cohesion-reviewer`                                                            |
| levels, declared dependencies, no cycles, blocks, legacy                                                                                                                                                                                                                                                                                | **planned**                                                                                 |

Each rule is proven by breaking it on purpose: `npm run test:eslint-plugin` runs ESLint's `RuleTester` with a valid and an invalid case per rule, and each rule was falsified once. A rule's message says what to do, not only what is wrong.

## Final validation

Final validation = lint → `format:check` → tests, and the first red step stops the run. In this repository `npm test` opens with `lint:style` and `format:check`; in a created project `npm run check` runs `lint`, `format:check`, `typecheck`, then `widgetarium check`. Prettier's settings and its exact version are the repository's, copied into the project's `package.json` by `create`.

Agents format on every edit: the `PostToolUse` hook in `.claude/settings.json` runs `prettier --write` on each file a Write or Edit touches, so `format:check` only catches a file written another way.
