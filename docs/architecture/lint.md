# Lint

Every rule in these pages is a folder, a file name or a type, so a tool checks it, not a review. A rule is switched on only after a count shows which files it would refuse. `node tools/lint-code.mts <roots>` runs the file rules (a package counts as a domain when its `package.json` says `"widgetarium": { "level": "domain" }`); the starters' refusals run in `app()` and `server()`; the type rules run in `npm run test:types`.

| Rule               | Refuses                                                                                                                                                                                       | Held by                                                     |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| features           | a file in `features/<feature>/` other than `contract.ts` and `handlers.ts`, or one nested deeper                                                                                              | `domain-layout`                                             |
| contracts          | a `handler(...)` call in `contract.ts`                                                                                                                                                        | `domain-layout`                                             |
| request names      | a request in `contract.ts` whose name is not `<domain>/<constant without suffix, kebab case>`                                                                                                 | `domain-layout`                                             |
| ui is drawn        | a file in `ui/` that is not `.tsx`                                                                                                                                                            | `domain-layout`                                             |
| adapters           | a file at the top of `adapters/<area>/` that is not `.adapter.ts`; a folder under it with no `<folder>.adapter.ts`; an import of a part of `adapters/<area>/<kind>/` from outside that folder | `domain-layout`                                             |
| guards             | a server module's request with no guard; anything after `PublicGuard`                                                                                                                         | type, `server()`                                            |
| idempotency        | a command with no `idempotencyKey`                                                                                                                                                            | type                                                        |
| provided           | a `provide` missing a key its handlers inject                                                                                                                                                 | type; `app()`, `server()` check the instance                |
| one handler        | two handlers for a request; a handler in a module its request's name does not name                                                                                                            | `app()`, `server()`                                         |
| sides              | a `runs: "server"` module in `app()`, a `runs: "client"` module in `server()`                                                                                                                 | `app()`, `server()`                                         |
| authenticate       | a guard that needs a user on a server with no `Authenticate`                                                                                                                                  | `server()`                                                  |
| guard injection    | a guard injecting a value the request's module does not provide                                                                                                                               | `server()`                                                  |
| server-only import | a client bundle importing a server module's `./module`                                                                                                                                        | **planned**: the `widgetarium-server` export condition (D9) |
| no foreign code    | a vault implementation, Obsidian host code, Hono or the oRPC server in the browser studio bundle                                                                                              | `test:web-canvas-bundle`                                    |
| size               | a file over 400 lines, a function over 80 (warnings from 250 and 50)                                                                                                                          | `file-size`, `function-size`                                |
| comments           | any comment but `TODO:` and `TRADE-OFF:`                                                                                                                                                      | `comments`, edit hook                                       |
| no top-level `let` | a top-level `let` in `contract.ts` or `handlers.ts`                                                                                                                                           | **planned**                                                 |
| starters only      | an import of a domain's `module.ts` by anything but a starter                                                                                                                                 | **planned**                                                 |
| server has no ui   | a `ui/` folder in a `runs: "server"` module                                                                                                                                                   | **planned**                                                 |
| generated entry    | a stale `index.ts` once `widgetarium generate` writes it                                                                                                                                      | **planned**                                                 |
| levels             | an import against the table in [README.md](README.md#imports); a package importing an app                                                                                                     | **planned**                                                 |
| public API         | an import of another package by any path but its `index.ts`                                                                                                                                   | **planned**                                                 |
| declared           | an import of a domain not listed in `package.json` dependencies                                                                                                                               | **planned**                                                 |
| no cycles          | a cycle in the graph of domains                                                                                                                                                               | **planned**                                                 |
| blocks             | hand-written pointer or scroll math in a block; a decision about request data in a block                                                                                                      | **planned**                                                 |
| legacy             | a new file in a `legacy/` folder; an import of `legacy/` from outside its owner                                                                                                               | **planned**                                                 |

Each check is proven by breaking it on purpose: write the file it must refuse, see it red, remove the file. A rule's message says what to do, not only what is wrong.
